# 软件需求规格说明书（SRS）

**版本** v0.1 设计稿  
**使用者** 在自有或获授权的实验环境中核验公开漏洞的安全研发人员

## 用户流程

操作者提供 CVE 编号、复现目标和资源限制。系统读取情报并固定缺陷与修复版本，生成补丁分析、源码线索和可执行计划。操作者审核计划后，系统在隔离环境中构建两个版本，生成或选取测试输入，按同一验证规则对照运行，最后导出带哈希清单的报告与证据。

## 首版适用范围

- 单操作者、单执行槽位，支持排队、查询、审核、进程重启后继续和证据导出。
- 一种目标形态：Linux x86_64 上可离线构建的开源 C/C++ 用户态命令行目标或库，且有同仓库的缺陷与修复提交、可审核的构建配方、能驱动漏洞路径的 harness，以及可用 ASan 判断的内存错误。
- 开发与 PR 使用合成双版本 fixture。发布候选另选一个有公开公告和可固定源码、依赖及种子的真实 CVE，在专用实验环境验收。选例与准入见 [任务 T01](tasks.md#t01-锁定案例与测试基线)。
- 首版用 Git、Tree-sitter、Clang/ASan、Docker 实现主路径。测试生成 Agent 先支持通过审核的 harness 和固定种子，受限 libFuzzer 搜索列为后续扩展。二进制目标由 Supervisor 识别并返回范围原因；Ghidra、CodeQL、AFL++、向量检索及远端对象存储列入扩展路径。

## 规范与验收

### REQ-01 任务输入与资源约束

提交必须校验 CVE 格式、复现目标、案例配置与预算，返回唯一任务 ID。超出上限或结构错误在排队前拒绝。结构合法但目标类型超出 MVP 范围的请求以 `BLOCKED` 结束并给出原因。默认每容器 2 vCPU、2048 MiB 内存、128 PID、512 MiB 可写空间；任务准备阶段和获批后的执行阶段分别最多 10 分钟和 20 分钟，审核时限 24 小时。执行阶段上限含恢复等待、重试和归档；每次验证回放默认最多 10 秒，且受阶段剩余时间约束。

### REQ-02 情报和版本可追溯

情报记录须保留来源、采集时间和内容摘要。缺陷版和修复版均解析为完整 Git 对象 ID，记录仓库、补丁依据及依赖锁定信息。情报冲突、缺失修复版或无法校验材料时，任务以 `BLOCKED` 结束并指出待补材料。

### REQ-03 可审核的分析与计划

补丁分析给出修改位置与差异证据，源码分析给出相关语法结构或候选调用点，推测须带证据引用和置信级别。计划固化两个提交、输入、harness、构建配方、运行镜像、目标签名、预算和隔离策略。审核批准与计划摘要绑定，拒绝、过期或计划失效时封闭执行入口。

### REQ-04 持久化与恢复

任务状态、审核决议、节点产物与工具尝试可查询。重启或重复命令须安全恢复，旧执行者无法提交结果。可恢复基础设施错误每逻辑步骤最多额外重试一次，超过时限终止。日志说明恢复、重试、拒绝或失败的原因。

### REQ-05 隔离构建和运行

所有目标代码的构建、harness 验证、执行均在受限工作环境内完成。目标进程无外网，使用非特权用户和显式资源配额。执行器发现隔离或配额无法落实时阻断任务。每次构建及回放产生可核对的退出状态、限额事件、运行时长及日志。

### REQ-06 可比测试输入

用经审核的 harness、触发候选种子和正常对照输入对两个版本执行。候选种子的字节与哈希固定。工具链、镜像、harness、依赖、编译参数、运行参数和输入应一致；构建源码提交允许不同。无法建立可比性时按 `INCONCLUSIVE` 记录。

### REQ-07 证据驱动的结论

每个版本先在新容器执行一次正常对照，再分别在新容器对同一候选种子执行两次。按以下优先顺序判定。

1. 缺少完整可比的记录、正常对照异常、候选结果间歇出现、出现其他崩溃、任一回放超时或资源耗尽时，给出 `INCONCLUSIVE`。
2. 缺陷版两次均命中经审核的 ASan 签名，修复版两次均完成预期退出且 ASan 日志无诊断，给出 `REPRODUCED`。
3. 两个版本对候选种子均完成预期退出且 ASan 日志无诊断，给出 `NOT_REPRODUCED`，结论限定在该种子、版本、环境及预算。
4. 其余完整运行组合均给出 `INCONCLUSIVE`，包括修复版仍命中同一签名。

签名由 ASan 错误类别及已审核的目标函数/源码路径匹配规则构成，须使用可符号化的记录。正常对照须满足案例配置声明的预期退出码及输出断言，且 ASan 日志无诊断。候选种子的预期正常退出码同样由案例配置声明。普通退出码、信号或模型推测不足以构成复现证据。

### REQ-08 报告与证据导出

报告包含版本信息、环境配置、测试输入摘要、异常证据、结论及其依据。证据清单列出文件角色、大小及 SHA-256。可离线验证清单，检查修改、缺件、路径穿越及多余文件。阻断或中途失败时保存已有证据和错误原因，基础设施无法写入时在任务状态中记录导出不可用。

### REQ-09 Agent 决策可审计

Supervisor 按预定义状态转移调度。模型以结构化结果提出分析建议，输出附证据引用。工具执行器按参数契约授权，审批、限额、状态流转和判定由确定性逻辑执行。外部文本作为数据处理，工具和日志中留存脱敏审计记录。

### REQ-10 可发布与可回退

合并前通过契约、单元、持久化、隔离和合成端到端回归。内部实验环境按不可变制品摘要晋级，经冒烟和真实案例验收。保留上一版制品摘要和部署配置，可演练恢复，保留既有审核记录与证据。

## 输出与异常

- 请求接收时输出任务 ID 和初始状态。查询输出当前阶段、审核状态、最后一次错误、制品可用性。终态输出结论或阻断原因。
- 参数错误、权限失败、材料冲突、构建失败、验证证据不足、制品写入错误使用独立原因码。成功生成报告与成功复现是两个独立事件。
- 已批准的计划发生材料或策略漂移时阻断任务，变更后的计划使用新任务重新审核。进程退出或可恢复的基础设施失败沿原任务恢复。
- 报告和工具输出的保留范围及共享权限见 [安全设计](security-design.md)。CLI、字段和错误码见 [接口契约](interface-contract.md)。

## 非功能要求

- **可恢复性**。审核与结果提交持久化。恢复时校验所有已完成步骤的制品引用，旧执行者不得更新当前状态。
- **可比较性**。使用锁定版本、固定种子、工具链镜像摘要与可观测退出结果；保留编译与运行参数以及资源限制。
- **可观测性**。事件至少带任务 ID、阶段、尝试序号、原因码和时长。必要日志缺失或截断会影响判定。
- **可移植性**。运行目标为 Linux x86_64。离线验包仅依赖契约及导出文件，校验文件完整性。
- **可测试性**。CI 使用离线合成案例与模型替身；真实案例在专用实验环境验收。

验收映射见 [测试与评估计划](test-plan.md)，发布门禁见 [CI/CD 与交付规范](ci-cd.md)。
