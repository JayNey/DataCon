# CI/CD 与交付规范

**适用环境** GitHub Actions 与内部 Linux 实验环境。流水线在实施阶段创建。

## CI 与合并门禁

1. **规范与静态检查**。校验 Markdown 相对链接、需求编号、契约示例、代码风格、类型和依赖锁定。契约变更须关联受影响的验收用例。
2. **测试**。运行单元和契约测试，启动 PostgreSQL 验证持久化，在一次性 Linux 运行器完成隔离探针和合成案例端到端测试。测试默认使用离线材料和模型替身。
3. **供应链检查**。扫描依赖、镜像和误提交的密钥。阻断未豁免的严重或高危发现。豁免记录范围、影响、责任人和到期日。
4. **合并条件**。上述必需检查全部通过并经维护者审阅。PR 工作流使用最小权限，第三方 Action 固定完整提交 SHA。来自外部贡献的代码在无部署凭证的一次性运行器执行。 [GitHub Actions 安全使用](https://docs.github.com/en/actions/reference/security/secure-use)

## 制品与候选发布

- 主分支合入后构建控制面镜像。运行工具链镜像按基础镜像和依赖锁定文件构建。候选记录源码提交、镜像摘要、SBOM、测试与扫描报告、契约版本和数据库迁移版本。
- 受保护发布环境按摘要拉取制品，验证来源与批准状态。测试及内部发布推广同一摘要。运行任务固定其计划批准的工具链镜像。
- 开发和 PR 上传合成案例的脱敏日志。真实案例的输入、完整诊断和证据包保存在受限实验环境。
- 候选环境执行 CLI 冒烟、数据库和制品可读性检查、隔离预检、合成双版本回归及公开案例验收。任何必要检查失败时停止推广。

## 发布、恢复与记录

1. 维护者核对候选制品和实验验收记录，批准推广。记录上一运行版本的镜像摘要、配置、数据库与证据存储位置。
2. 切换前暂停接收新任务并等待执行槽位清空，保留待审任务与计划摘要。迁移前创建可恢复的备份并检查兼容性。
3. 按摘要部署并运行冒烟。通过后恢复接收任务。候选版本无法读取既有状态或隔离预检失败时触发回滚。
4. 回滚时恢复上一已验证的镜像与配置。采用前向兼容迁移，使上一版本能读取既有任务。涉及不可逆迁移的变更先验证备份恢复及变更窗口内的写入保护，确保审核和证据引用可恢复。
5. 归档源码提交、发布及回滚摘要、操作者、迁移记录、冒烟与验收结果。真实案例证据记录存储引用及清单摘要。

## 触发规则

- PR 触发合并门禁。
- 主分支触发构建和制品验证。
- 发布候选触发内部环境推广与公开案例验收。
- 手动回滚使用受保护环境和既有版本摘要。
