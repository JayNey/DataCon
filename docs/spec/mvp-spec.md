# MVP 功能规格说明

**交付目标** 在 Linux 实验环境中完成一次从任务提交到证据导出的双版本对照实验。

## 首版功能边界

- **入口**。本地 CLI，单操作者、单执行槽位。支持提交、查询、审核、恢复和导出。
- **材料**。每次任务使用一个预先注册的 C/C++ 案例配置，提供公告快照、缺陷与修复提交、锁定依赖、离线构建配方、harness、固定候选种子和正常种子。
- **分析**。可追溯的 CVE 情报、Git diff 与 Tree-sitter 结构线索。模型可提供补充假设，离线流程可完整演示。
- **执行**。批准后在一次性容器构建双版本，ASan 工具链与参数一致。每个版本进行一次正常对照和两次候选回放，分别记录证据。
- **交付**。输出 Markdown 报告、结构化报告和离线可核验的证据清单。
- **后续范围**。二进制逆向、深度静态分析、自动 fuzzing、自动生成可执行 harness、外部对象存储、向量检索、Web 界面和多租户。

## 验收场景

### MVP-01 合成正例

给定固定的合成双版本案例。提交并查看计划，确认实际提交与摘要，批准后构建并完成六次回放。两版正常输入均满足断言，缺陷版两次命中同一预期 ASan 签名，修复版两次正常完成。任务返回 `REPRODUCED`，导出的清单可校验。

### MVP-02 正常候选与证据缺口

给定正常的候选输入时，六次回放均按预期完成，任务返回 `NOT_REPRODUCED`。移除一次必要回放证据或注入超时后，判定为 `INCONCLUSIVE`，报告引用缺失角色或配额事件。

### MVP-03 审核与恢复

在待审阶段重启进程，原计划仍可查询。拒绝、过期或摘要不符时目标代码执行次数为零。批准后，在工具结束、结果入库前终止工作进程，恢复后核对旧尝试并继续。结果只有一个有效版本。

### MVP-04 超限与验包

运行资源探针验证容器的网络和配额策略。篡改已导出文件、增加额外文件或引入路径越界清单条目时，离线校验失败并指明原因。

### MVP-05 公开案例

从受信公告和固定仓库导入一个准入案例。运行通过 CI 的候选制品，按同一双版本规则得出 `REPRODUCED`，由复核者核对提交、正常对照、ASan 签名、输入摘要与证据包。案例的具体编号和材料按 [任务 T01](tasks.md#t01-锁定案例与测试基线) 选定。

## 完成条件

MVP-01 至 MVP-04 通过合成验收。MVP-05 在内部实验环境通过并形成可复查记录。发布候选还须满足 [CI/CD 规范](ci-cd.md) 的自动门禁、推广与回滚要求。
