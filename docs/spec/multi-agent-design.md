# 多 Agent 协作设计

## Supervisor 与专业 Agent

Supervisor 拥有图路由权。每个专业 Agent 消费已验证的任务上下文，返回自己的结构化结果与证据引用。Supervisor 校验结果并提交业务状态，专业 Agent 不直接改写其他节点的记录。

1. **情报收集 Agent**读取 CVE、NVD、维护方公告或离线快照，生成带来源、采集时间与摘要的情报。资料冲突时输出相互矛盾的来源，供操作者修订案例配置。
2. **版本定位 Agent**通过 Git 解析 tag 和 commit，确认对象在案例仓库中可用，记录依赖锁定与缺陷版/修复版依据。缺少可验证的版本对时返回阻断原因。
3. **补丁分析 Agent**提取 diff、修改路径和根因假设。将补丁中的事实与待验证推断分别标注。
4. **源码分析 Agent**用 Tree-sitter 提取语法节点、候选入口和调用点。后续引入 CodeQL 做跨过程调用图与数据流分析。
5. **逆向分析 Agent**负责二进制分支。MVP 返回 `UNSUPPORTED_TARGET`。后续接入 Ghidra 获取符号、反汇编和交叉引用。
6. **环境构建 Agent**按已批准计划在隔离环境中构建两个提交，返回编译参数、二进制摘要、工具链及日志。
7. **测试生成 Agent**物化并校验固定 harness、候选种子和正常对照。后续接入受限 libFuzzer 或 AFL++，将新候选转交固定输入验证流程。
8. **验证 Agent**对两个版本运行对照和候选输入，汇总规范化 ASan 证据并交给确定性判定器。判据以 [SRS](srs.md) 为准。

## 任务分发与人机协作

- 首版采用串行任务图。准备阶段依次执行情报、定位、补丁和源码分析。材料齐备后冻结计划并等待审核。
- 审批绑定 `job_id`、`plan_digest`、操作者与时限。待审节点仅展示已保存的计划，恢复节点从数据库读取有效决议后才能进入构建。
- 发现二进制目标、证据冲突、计划变更或安全策略失败时，由 Supervisor 路由到归档与阻断终态。
- 工具失败先按契约归类。明确的瞬时基础设施故障允许一次重试。目标回放的超时、OOM、崩溃属于观测，交给判定器。无有效回放的构建失败归入运行失败。
- 将模型建议限制在结构化分析结果。模型给出候选符号、证据引用和置信级别，程序校验引用和类型。证据缺失时保留为未验证线索。外部文档、源码注释和日志都作为输入数据处理。
- 模型无权批准计划、修改资源配额、调用任意工具、提交终态或生成独立结论。离线测试使用同一输入输出契约的替身。

## 状态管理与恢复

- PostgreSQL 业务记录确定已提交的阶段与制品，图检查点标记调度位置。恢复节点每次读取业务状态，再决定返回既有结果或继续执行。LangGraph 在恢复中断时可重新进入节点起点，副作用通过持久化步骤去重。 [LangGraph 中断机制](https://docs.langchain.com/oss/python/langgraph/interrupts)
- 以 `job_id`、`stage`、`step_key` 标识逻辑调用，尝试追加 `attempt_no`。执行前持久化尝试，容器按尝试标识确定性命名。进程恢复时核对执行器记录，优先收回有效结果；确认容器停止且结果无法恢复后才能消耗重试次数。
- 单执行槽位领取带期限的租约。领取时增加执行代次，写回结果时核对代次、阶段版本、计划摘要和租约。过期执行者的写回被拒绝。无法确认旧容器停止时关闭该执行槽位。
- 制品先按摘要完整写入，再提交业务引用。重复执行可复用已验证的制品。归档同理，校验完成后才发布证据包引用。

## 可观测性

审计事件包含调用开始、材料校验、审核决议、阶段完成、工具终止、重试、判定与归档。事件使用任务和尝试标识串联。记录所用策略、提示模板和模型配置版本，并保留结构化输出及来源引用。
