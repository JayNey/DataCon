# 项目愿景与范围说明书

**项目** DataCon 公开漏洞复现平台  
**版本** v0.1 设计稿

## 研究背景

从公开漏洞公告到可复查的复现结论，需要定位受影响版本、理解修复补丁、重建依赖环境、构造输入和核对运行证据。这些步骤分散在公告、源码仓库、构建日志和实验笔记中。版本漂移、偶发崩溃和缺少修复版对照都可能使同一案例得到不同结论。

## 项目目标

- 将 CVE 情报、版本定位、补丁和源码分析、隔离构建、测试与验证串成可恢复的流程。
- 让 Supervisor 协调专业 Agent，保留各节点的证据来源与执行记录。操作者在目标代码执行前审核冻结的计划。
- 交付可离线核验的报告与证据包，使审阅者能追溯结论使用的提交、环境、种子和运行记录。
- 用 SDD 管理需求与契约，用 MVP 验证最短业务闭环，用 Agentic Engineering 实现受约束的协作，用 TDD 保证关键行为，用 CI/CD 保证发布一致性。

## 首版范围

面向单操作者、单执行槽位的 Linux x86_64 实验环境。采用本地 CLI，对一个已知可离线构建、有同仓库修复提交和固定测试输入的 C/C++ 用户态案例进行双版本 ASan 对照。开发和 PR 使用合成双版本案例，发布候选另用一个经过材料与授权核查的公开 CVE。

架构预留二进制逆向、深度静态分析、覆盖率引导模糊测试、远端对象存储和向量检索。Web 控制台、多租户、网络服务漏洞和未知漏洞自动发现列为后续范围。

## 成功标准

- 合成案例在标准环境中可从提交运行至证据导出，正例与正常种子得到各自预期结论。
- 一次审核暂停和一次工具执行中断均可恢复，执行仍受已批准的计划约束。
- 一个已选定的公开案例满足双版本 ASan 对照判据，另一名审阅者可凭证据包在同类环境复查。
- 通过规定的自动门禁，能够将同一候选制品推广到内部实验环境，并完成上一版本的回滚演练。

## 角色与设计基线

操作者提交、审核并查看自己的实验任务。项目维护者管理案例、依赖锁定和发布。复核者检查复现判据与证据。

本地 CLI、PostgreSQL、本地内容寻址存储、GitHub Actions 与实验 VM 为首版设计选择。实际 CVE、可用基础镜像和工具版本在后续实施时按准入条件选定和锁定。数值预算为初始验收基线。
