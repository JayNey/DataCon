# 产品需求文档（PRD）

**版本** v0.1 设计稿

## 用户与场景

- **安全研发人员**收到一个公开 CVE，需要在实验室确认给定版本和种子能否稳定触发已知问题。用户希望一次提交后查看进度，在执行前核对材料，在结束后获得可复查的证据。
- **结果复核者**需要确认两个版本是否使用相同环境和测试输入，以及 ASan 异常是否符合目标签名。
- **项目维护者**需要把一个已通过实验的案例固化为测试，发现 Agent 输出、工具版本或隔离策略变更带来的回归。

## 功能模块与优先级

- **P0 任务入口**。录入 CVE、目标和预算，查看阶段、审核请求、终态与原因。对应 REQ-01、REQ-04。
- **P0 情报与分析**。整理来源、解析提交、提取补丁与源码线索，输出冻结计划。对应 REQ-02、REQ-03、REQ-09。
- **P0 审核与执行**。批准或拒绝指定计划，在限额内构建两版并回放固定输入。对应 REQ-03、REQ-05、REQ-06。
- **P0 验证与报告**。判定复现结果，导出报告和证据清单，支持离线验包。对应 REQ-07、REQ-08。
- **P0 交付**。用固定案例通过合并门禁、制品推广与实验环境验收。对应 REQ-10。
- **P1 分析与探索扩展**。加入 CodeQL、受限 fuzzing、可查询的历史证据。
- **P2 目标与运行环境扩展**。Ghidra 二进制逆向、一次性 VM 执行后端、远端对象存储、跨任务向量检索。

## 主工作流

1. 提交目标后获取任务 ID。输入不合法时，CLI 返回具体字段错误。
2. 观察任务准备进度。材料可用时，CLI 显示两个提交、来源、分析线索、输入与 harness 摘要、资源预算和计划摘要。
3. 审核指定计划。批准后开始隔离实验，拒绝或过期时显示阻断原因。
4. 查看结果。用户可以展开各版本的正常对照、候选回放、ASan 摘要和结论原因。
5. 导出私有证据包。在具备访问权限的环境中离线验证清单及文件摘要。

材料缺失时，用户根据原因补齐案例配置并新建任务。执行环境失败时，用户可从保留的错误记录定位问题。任务恢复后继续已固定的计划。

## 体验验收

审核视图能在执行前回答「将运行哪个版本、执行什么、使用哪些输入、限制是什么」。结果视图能回答「两个版本实际发生了什么、证据在哪里、该结论适用什么条件」。首版具体边界见 [MVP 功能规格](mvp-spec.md)，可测试行为见 [软件需求规格](srs.md)。
